Git for self-learning software

Software should learn

How it works

01

Try a hypothesis.

When the system is unsure, turn that uncertainty into a bounded experiment.

02

Remember the result.

Keep what worked, what failed and why directly in the repository.

03

Gate architecture.

Important architectural changes move forward only when the required evidence exists.

One concrete example

Should we change the storage architecture?

Instead of deciding in chat, define what must be true, run the experiment, attach the evidence and record the decision. 

hypothesis
"partitioned Postgres is fast enough"

        ↓

evidence
"p95 query: 142 ms"

        ↓

gate
"target: < 200 ms"

        ↓

decision
accepted

Why Git

The knowledge stays with the code.

No separate memory service is required. Experiments, evidence and decisions travel with the repository, survive agent handoffs, and remain available to whatever model works on the project next.
