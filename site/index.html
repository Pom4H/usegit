The problem

Today the process lives inside the agent invocation.

When the invocation ends, someone has to reconstruct what was in progress, what is safe to run next, which CI result still applies, and whether a decision was actually validated. usegit moves that state into the repository.

What the code actually does

The repo becomes a small development runtime.

01

Work survives the agent.

A task can become awaiting, release its lease, and store success/failure continuations. A fresh agent resumes it later from Git alone.

refs/usegit/work/*
02

Parallel work fails safe.

File scopes, semantic resources, dependencies and compare-and-swap refs prevent silent double ownership and surface collisions before workers overlap.

claim-next · scopes · resources
03

Cheap work stays cheap.

Low uncertainty + objective oracle + explicit success/evidence contract can enter the worker queue. Architecture and ambiguity stay in control.

workerReady[] / controlQueue[]
04

Evidence has a subject.

Observed and attested evidence names its source, environment and exact Git tree. Change the tree and acceptance requires revalidation.

tree-exact acceptance

A handoff without chat history

Stop at CI.
Continue tomorrow.

No polling agent needs to stay alive. The continuation is durable, and the next invocation starts by asking the repository what exists. 

$ usegit start \
  --goal "reduce renderer cost" \
  --hypothesis "cache probe visibility" \
  --scope "src/render/**,test/render/**" \
  --success "p95 improves >= 0.5 ms" \
  --evidence-plan "GPU CI benchmark" \
  --uncertainty low \
  --oracle objective

→ WORK-A12F · ready

$ usegit claim-next
→ WORK-A12F · active

$ usegit await WORK-A12F \
  --event ci:gpu-benchmark \
  --on-success "accept if metric passes"

→ awaiting · lease released

# later, from a fresh invocation

$ usegit context
→ awaiting: WORK-A12F

$ usegit resume WORK-A12F \
  --result success \
  --evidence "p95 improved 0.8 ms" \
  --evidence-kind observed \
  --evidence-source "github-actions:412"

$ usegit finish WORK-A12F --decision accepted

Why this becomes self-learning

The next decision starts from the last result.

usegit does not train model weights. It makes development outcomes reusable. Accepted, rejected and falsified hypotheses remain in the repository, causal history is compressed into a small context packet, and usegit next chooses the next unresolved experiment from accumulated state.

The practical effect is simple: the system can deepen the domain only when uncertainty appears, while avoiding hypotheses that were already falsified under the same conditions.

Architecture stays gated

Not every decision belongs to a worker.

In the current routing policy, architecture decisions are an explicit blocker for automatic worker execution. They stay in the control lane until a human or deeper reasoning process defines the contract and evidence.

ordinary bounded change→ worker architecture decision→ control conflicting evidence→ control repeated failure→ control
