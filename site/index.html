Quick start ↗
01 / MODEL

Three things the repository should remember.

01

Work

Goal, hypothesis, ownership, scope and the continuation required to resume later.

start · await · resume
02

Evidence

Observed results stay attached to the exact Git tree and retain where they came from.

tree · source · result
03

Decision

Accepted, rejected and falsified ideas survive the chat instead of being rediscovered.

pending · accepted · rejected
02 / HANDOFF

Stop at CI. Continue from Git.

No polling agent has to stay alive just to remember what happens next.

START Define one causal change

goal + falsifiable hypothesis

WORK Implement it

state lives in the repository

AWAIT Persist the continuation

the current invocation can end

RESUME Read evidence and continue

fresh agent, same state

$ usegit await WORK-A12F --event ci:test
→ awaiting · continuation stored · lease released

# later, in a fresh invocation
$ usegit context
→ awaiting: WORK-A12F
$ usegit resume WORK-A12F --result success
03 / EVIDENCE

Green only counts for the code that was tested.

usegit records provenance with the result. If the Git tree changes, the old result cannot silently accept the new code.

A clean pass, a retry pass, and an agent saying “looks good” remain different facts.
