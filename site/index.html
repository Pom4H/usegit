The problem

Chat should not be process state.

When an agent stops, the repository should still know what was in progress, what it was trying to prove, what CI observed, and what is safe to do next.

Small by default

Start simple. Add coordination only when you need it.

01

Work survives the chat.

A WORK can wait for CI, release ownership, and be resumed later by a fresh agent from Git alone.

start · await · context · resume
02

The next agent knows what happened.

Hypotheses, failed attempts, evidence and decisions stay connected instead of disappearing with the conversation.

hypothesis → evidence → decision
03

Parallel work can fail safe.

When you need multiple workers, leases, scopes and Git compare-and-swap prevent silent double ownership.

claim-next · scopes · resources
04

Green is not enough.

Evidence belongs to an exact Git tree. Retry passes stay distinguishable from clean passes, and tampered evidence fails closed.

tree-exact evidence

A handoff without chat history

Stop at CI.
Continue later.

You do not need a polling agent to stay alive. Persist the wait, let the invocation end, and resume from the repository. 

$ usegit start \
  --goal "reduce renderer cost" \
  --hypothesis "cache probe visibility"

→ WORK-A12F · active

$ usegit await WORK-A12F \
  --event ci:test \
  --on-success "finish if valid"

→ awaiting · agent can exit

# later, from a fresh invocation

$ usegit context
→ awaiting: WORK-A12F

$ usegit resume WORK-A12F \
  --result success \
  --evidence "tests passed" \
  --evidence-kind observed \
  --evidence-source "github-actions:412"

$ usegit finish WORK-A12F --decision accepted

Evidence that means something

A result only proves the code it actually tested.

usegit records the source and exact Git tree for observed evidence. Change the tree and the old result no longer accepts the new code.

A clean first pass, a retry pass and an agent saying “looks good” are different facts. usegit keeps them different.

Only when you need more

Scale from one agent to many without changing the model.

The same WORK state can later add scopes, dependencies, semantic resources and a worker queue. The basic workflow stays the same: work, evidence, decision.
