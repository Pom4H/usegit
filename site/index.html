Git substrate for self-learning systems

Let the system learn
the domain when it needs to.

usegit turns development into a persistent learning loop. The system starts with the model it has, deepens the domain only when uncertainty blocks progress, stores experiments as durable knowledge, and crosses architectural boundaries only when evidence satisfies an explicit gate.

The idea

Do not model the whole domain up front.

A self-learning software system should not require a complete ontology before it can act. It should operate with the smallest useful model, notice where that model stops being sufficient, and create a focused learning loop exactly there.

In usegit, that loop is visible in the repository: intent, hypothesis, work, evidence and decision survive individual model invocations. The next agent inherits the accumulated domain knowledge instead of rediscovering it from chat.

Progressive domain deepening

Learn only at the edge of uncertainty.

Cheap execution continues while the contract is clear. Ambiguity is escalated into a bounded experiment. Once the evidence changes what the system knows, that result becomes part of the repository.

Evidence-gated architecture

Architecture is not a chat opinion.
It is a state transition with a gate.

Mark a change as architectural, define what would make it safe to accept, collect evidence on the exact tree, and only then let the system cross the boundary. 

$ usegit start \
  --goal "replace historian storage model" \
  --hypothesis "partitioned Postgres meets retention and query targets" \
  --architecture-decision \
  --success "p95 query < 200 ms; retention cost within budget" \
  --evidence-plan "replay production-shaped workload in CI"

→ route: control / deep
→ status: active

$ usegit evidence WORK-ARCH-17 \
  --kind observed \
  --source "ci:historian-benchmark-412" \
  --result success

$ usegit finish WORK-ARCH-17 --decision accepted

→ gate passed for the exact validated tree

Start with one repository

No service to deploy.

usegit is deliberately small: Git objects, refs, notes and a CLI. Existing history stays untouched. The first adoption commit becomes the bootstrap boundary.
